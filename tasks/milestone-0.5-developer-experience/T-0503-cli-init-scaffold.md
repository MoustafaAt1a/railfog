## Scope

**In scope**:
- `cli/init.ts`: Implement `rail init [directory]` command that initializes a new RailFog project by generating:
  1. `railfog.toml`: Valid project configuration with `name`, sample HTTP function (`api`), route mapping (`/api`), and permissions per PLAT-6. Also supports `--template=worked-example` to generate the complete canonical flow from `docs/contracts/worked-example.md`.
  2. `functions/`: Starter function code importing types from `sdk/typescript/mod.ts`.
  3. `deno.json`: Pre-configured with recommended tasks (`dev`, `test`, `check`, `lint`) and import maps.
  4. `.gitignore`: Excluding `.railfog/`, build artifacts, and local SQLite databases.
- Wire `rail init` subcommand into `cli/main.ts`.
- `cli/init_test.ts`: Unit and integration tests verifying directory creation, file content correctness, and verification that the generated project immediately passes `rail check` (T-0504).

**Out of scope**:
- Remote cloud provisioning or deployment (handled by `cli/deploy.ts`).
- Interactive TUI wizard with complex prompts (keep minimal and deterministic).

## Interface to implement

```typescript
// cli/init.ts

export interface InitOptions {
  directory: string;
  projectName?: string;
  template?: "minimal" | "worked-example";
  force?: boolean;
}

export interface InitResult {
  targetDir: string;
  filesCreated: string[];
}

export async function runInit(options: InitOptions): Promise<InitResult>;
```

## Acceptance criteria (Given/When/Then)

1. Given a non-existent or empty target directory, when running `rail init my-app`, then it creates `railfog.toml`, `functions/api.ts`, `deno.json`, and `.gitignore`.
2. Given the generated `railfog.toml`, when inspected, then it specifies `name`, `[functions.api]` entrypoint, permissions, and route pattern matching `PLAT-18` and `FN-1`.
3. Given `rail init --template=worked-example`, when generated, then it generates `functions/api.ts`, `functions/processor.ts`, and `railfog.toml` matching the canonical worked-example specification in `docs/contracts/worked-example.md`.
4. Given an existing non-empty directory without `--force`, when running `rail init`, then it aborts with a descriptive error and does not overwrite existing files.
5. Given any project generated by `rail init`, when validated with the static config validator (`cli/check.ts`), then validation succeeds with zero errors.
